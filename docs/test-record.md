## 3. 信号级网关

模拟器发送：

```
0x200 车速 60.00 km/h、转速 3000、档位 3、SOC 80
0x210 电机温度 110℃
0x100 车门 0x5、灯光 3
0x110 灯光命令 近光
```

域控制器输出：

```
0x101  speed=60.00 km/h  door=0x5  light=0x2  cnt 递增
0x201  torque_limit=500 (50.0%)
```

结论：

- 车速从 CAN1 解包后重新打包到 CAN2 0x101
- 车门/灯光命令从 CAN2 汇总到 0x101
- 电机温度 raw=150 → 物理 110℃ → 限扭 50%

---

## 4. 接收超时

模拟器停止发送 0.5 s 后：

```
0x101  speed=INVALID     door=0xF  light=0x7
0x201  torque_limit=1000 (100.0%)
```

恢复发送后：

```
0x101  speed=60.00 km/h
0x201  torque_limit=500 (50.0%)
```

结论：

- 4 个 Rx IPdu 的 ComTimeout / ComFirstTimeout 生效
- 超时替换值正确（0xFFFF / 0xF / 0x7）
- 应用层对无效信号不执行降扭

## 7. 问题定位记录（面试可讲）

### 7.1 Com_Init HardFault

- 现象：上电即 HardFault，PC 停在 Com_Init
- 定位：生成的 `Com_PBcfg.c` 初始化缺少 `IpduGroupRefPtr`，指针整体错位
- 修复：补上该字段，编译警告消失

### 7.2 Dcm 0x2E 卡死在 0x78

- 现象：多帧写 VIN 后 Dcm 永久 pending，后续所有服务被 0x78 阻塞
- 定位：
  1. 旧工程 VIN 读写是空桩，从未真正走 NvM
  2. 真实 NvM 写不完成
  3. 根因：`Mem_43_INFLS_Init(&Config)` 传了非空指针，驱动直接跳过初始化
- 修复：`Mem_43_INFLS_Init(NULL_PTR)`

### 7.3 接收超时不生效

- 现象：停发报文后信号一直保持旧值
- 定位：
  1. Rx IPdu 未加入 Com IPdu 组 → 组启动时不会初始化 DM
  2. 只调用 `Com_IpduGroupStart`，没有调用 `Com_EnableReceptionDM`
- 修复：加入默认组 + 启动后使能接收 DM

### 7.4 扭矩限制误触发

- 现象：未收到 0x210 时 0x201 输出 300（30%）
- 定位：SOC 初始值 0，被误判为低电量；温度 raw 未减 offset
- 修复：只对有效信号做保护；温度按 raw-40 换算
